# @translifyhq/client

Runtime client for [Translify](https://translify.tommasofeltrin.work) delivery. It fetches the published bundle of a locale, caches it, revalidates it with `ETag` / `304`, and hands your app plain strings. It formats nothing: your i18n library (i18next, react-intl, FormatJS) keeps doing that.

Zero dependencies, under 3 KB min+gzip, ESM and CJS, typed keys generated from your live project.

## Install

```sh
npm install @translifyhq/client
```

Node 20 or newer, and every evergreen browser. The package uses `fetch`, `URL` and `AbortController` and nothing else.

## Quick start

```ts
import { createTranslify, localStorageStorage } from '@translifyhq/client';

const translify = createTranslify({
  baseUrl: 'https://translify.tommasofeltrin.work/api', // the API origin including /api; required
  project: 'acme-ecom',
  environment: 'production',
  key: 'pk_…', // a publishable delivery key from the project's API keys
  storage: localStorageStorage(), // optional: survive page loads (memory only when omitted)
});

const bundle = await translify.load('it-IT');
bundle['cart.title']; // "Il tuo carrello"
translify.get('it-IT', 'cart.title'); // same, synchronous
```

`baseUrl` is required. The package ships no default hostname: the hostname is yours to pin, and a published package could not change a baked-in default later without breaking installed versions.

The key is a **publishable** key (`pk_…`). It ships in your browser bundle by design and travels as `?key=` so the edge cache can key on it; a secret key (`sk_…`) is refused before any request is made.

Keys are named `<namespace>.<keyName>`, exactly as the delivery endpoint serves them. Pass `namespaces: ['cart', 'checkout']` to load only those (one request each, merged into one bundle).

## Caching

Each (locale, namespace) is an **entry**: the bundle, its `ETag` and when it was last confirmed. Entries live in memory and, when you pass a `storage`, in that store too under keys prefixed `translify:v1:` (the key's last four characters are part of the storage key, the key itself never is).

`load(locale)`:

1. An entry held in memory or storage is used **immediately**: `load` resolves, listeners fire, your UI renders. The entry is then revalidated in the background with `If-None-Match`.
2. With no entry, the bundle is fetched; `load` rejects with a `TranslifyError` when that fails.
3. Revalidation answers `304` (nothing changed, the bundle keeps its identity) or `200` (new bundle, stored, listeners fire).

When a background revalidation fails, `load` has already resolved, so the failure goes to `onError` and the entry is handled by kind:

- **Transient** (`NETWORK`, `RATE_LIMITED`, `SERVER`): the entry stays in memory and storage. The app keeps working through an outage.
- **Definitive** (`UNAUTHORIZED`, `NOT_FOUND`, `BAD_REQUEST`): the server said this URL and key no longer serve a bundle (key revoked, environment archived, locale disabled). The stored entry is deleted, the in-memory bundle is kept for the rest of the session so the page does not blank, and the next page load fails loudly.

A publish reaches the app on the next `load` or `refresh(locale)`. A `429` is reported once and never retried by the package: the cache is the remedy.

`localStorageStorage()` turns itself into a no-op when `localStorage` is missing, disabled or full. `memoryStorage()` is the default. Any object with `get`, `set` and `delete` (sync or async, string values) works as a `storage`.

## Typed keys

```sh
TRANSLIFY_DELIVERY_KEY=pk_… npx @translifyhq/client types \
  --base-url https://translify.tommasofeltrin.work/api \
  --project acme-ecom --environment production --locale en-US \
  --out src/translify-keys.d.ts
```

It reads the live bundle of one locale (the one whose key set defines your app, usually the source locale) and writes:

```ts
// Generated by @translifyhq/client types. Do not edit.
// acme-ecom / production / en-US — 9 keys
declare module '@translifyhq/client' {
  interface TranslifyKeys {
    'cart.title': string;
    'cart.totals.total': string;
  }
}
export {};
```

With that file in your project, `translify.get(locale, key)` autocompletes and refuses typos; without it every key is a `string`. Add `--namespace cart` (repeatable) to type a subset. In CI, `--check` writes nothing and exits 1 when the file on disk is out of date. Output is deterministic (sorted keys, LF, trailing newline).

## Using with React

The client exposes a sync read and a change subscription, which is exactly what `useSyncExternalStore` wants. No React package needed:

```tsx
import { createContext, useContext, useEffect, useSyncExternalStore } from 'react';
import { createTranslify, type TranslifyClient, type TranslifyKey } from '@translifyhq/client';

const TranslifyContext = createContext<TranslifyClient | null>(null);

export function TranslifyProvider({ client, children }: { client: TranslifyClient; children: React.ReactNode }) {
  return <TranslifyContext.Provider value={client}>{children}</TranslifyContext.Provider>;
}

export function useTranslify(locale: string) {
  const client = useContext(TranslifyContext);
  if (client === null) throw new Error('TranslifyProvider is missing');

  useEffect(() => {
    client.load(locale).catch(console.error);
  }, [client, locale]);

  const bundle = useSyncExternalStore(client.subscribe, () => client.bundle(locale));

  return (key: TranslifyKey) => bundle?.[key] ?? key;
}
```

Hand the returned strings to your formatter of choice. The example app in [translify-examples](https://github.com/chesterbrains/translify-examples) wires the client into an i18next backend.

## API

```ts
createTranslify(options): TranslifyClient

options.baseUrl      string            required, the API origin including /api
options.project      string            required
options.environment  string            required
options.key          string            required, a pk_ key
options.namespaces   string[]          optional, lowercase kebab-case
options.storage      BundleStorage     optional, default memoryStorage()
options.fetch        typeof fetch      optional, default globalThis.fetch
options.onError      (TranslifyError) => void   optional, background failures

client.load(locale)        Promise<TranslifyBundle>   resolves once a bundle is usable
client.get(locale, key)    string | undefined         sync, never fetches
client.bundle(locale)      TranslifyBundle | undefined   same object until it changes
client.subscribe(fn)       () => void                 fn() after any bundle changes
client.refresh(locale)     Promise<TranslifyBundle>   revalidate now, rejects on failure
client.dispose()           void                       abort requests, drop listeners
```

`createTranslify` validates synchronously and throws `TranslifyError` with code `INVALID_OPTIONS` on a bad option.

## Errors

Every error is a `TranslifyError` with a `code`, a `message` that never contains the key, and `status` when there was a response.

| Code | When | Message |
| --- | --- | --- |
| `INVALID_OPTIONS` | a required option is missing, `baseUrl` is not an absolute http(s) URL, the key is a secret key, a namespace is not kebab-case, or the client was disposed | names the option |
| `UNAUTHORIZED` | 401 or 403 | `delivery key refused: missing, revoked or not a publishable key` |
| `NOT_FOUND` | 404 | `project, environment or locale not found, or nothing published` |
| `BAD_REQUEST` | 400 | `malformed project, environment, locale or namespace` |
| `RATE_LIMITED` | 429 | `delivery rate limit reached` |
| `SERVER` | any other status, or a body that is not a bundle | `delivery answered <status>` or `unexpected delivery body` |
| `NETWORK` | `fetch` rejected (offline, CORS, aborted) | `network error: <cause>` or `request aborted` |

## Exit codes

For `npx @translifyhq/client types`:

| Exit | Meaning |
| --- | --- |
| 0 | file written, or `--check` found it up to date |
| 1 | `--check`: the file is missing or out of date |
| 2 | usage: a flag or the key is missing, or the key is a secret key |
| 3 | delivery refused the request, or the locale has no published keys |
| 4 | network failure |

## Why no t()

Delivery serves raw ICU strings, and formatting them well needs a formatter with plural rules and number and date support. Every serious web app already ships one through its i18n library; bundling another would tax every user of this package for a feature their framework provides. The client stays a string vault; if standalone formatting is ever needed it can arrive as an opt-in subpath.
